Which apps can become an agent toolkit today?

For each app on a 100-app list, an agent researched the public docs for auth, access to credentials, API surface, an existing MCP server and Composio catalog status, then gave a buildability verdict. Every claim carries a quote from the page it came from, and each quote was checked against the live page.

    The agent

    An async Python pipeline. Composio's Connect MCP endpoint supplies the catalog search and the paid web tools; a model does the reading; a program and a second model do the checking.

    1. App listName, website hint and category for each app, in data/apps.csv.
    2. Composio lookupsComposio's own catalog search (free) for an existing toolkit, and one Composio web search for an MCP server. Every call is logged with its charge.
    3. Researcher modelReads official docs with a free direct page fetch. Composio search and extract are rationed per app.
    4. Evidence ruleA field with no quoted evidence is reset to unknown. No quote, no claim.
    5. Quote checkA program fetches every cited URL itself and string-matches the quote against the page.
    6. Critic modelSees only the claims and the matched quotes, and judges whether the quotes prove each field.
    7. One repair attemptFields that fail are researched once more. Still failing: flagged for a human.
    8. RecordWritten to disk as each app finishes, with its evidence, check results and cost.

    Where a human was needed

    Records flagged for review

      For agents

      The full dataset is embedded in this page as JSON in <script type="application/json" id="dataset">. Keys: apps (every app on the list), records (one per researched app, with evidence, verification, usage and the Composio call log), flat (one row per researched app using the field names below), process_notes, audit. The same data is in the repository as data/results.jsonl, data/apps.json and data/apps_flat.csv.

      Flat fields.

      Values. access_tier: self_serve_free, self_serve_trial, paid_plan, admin_approval, partner_or_sales, unknown (the most accessible path to credentials for a developer who is not a customer). buildability_verdict: Ready_Now, Conditional, Blocked_No_Public_API, Blocked_Partner_Gated, Unknown. primary_blocker: none, trial_only, paid_plan, partner_gate, admin_approval, no_public_api, narrow_api, docs_gated, other. mcp_maturity: generally_available, beta_or_pilot, announced, not_applicable, unknown. deployment_model: cloud, self_hosted, both, unknown. confidence_score is computed: the share of a record's checked fields that the verification step marked supported. Quote check results: exact, exact_rendered, too_short, not_found, unreachable.
